## Summary

We use AI as a **pipeline of agents with human checkpoints**, not as a single chat. A planning agent turned our design doc and slides into a build spec ([BUILD_PLAN.md](BUILD_PLAN.md)). An execution agent builds the app one phase at a time and stops for human approval. A separate evaluation agent tests the result. So far only the planning stage has run. Every Claude Code session in the repo is logged automatically, so this report is built from evidence rather than memory.

## How we work with AI

1. **Planning agent** (done, session `be960576`). It reads the specs, asks us the open decisions as multiple choice, and writes a spec another agent can follow. That spec includes acceptance criteria and a list of points where the agent must stop and ask a human.
2. **Execution agent** (next). It follows BUILD_PLAN phase by phase. Each phase gets a branch, a plan the human approves, the build, a green `dotnet build`/`dotnet test` run and a PR.
3. **Evaluation agent** (Phase 7). This is a separate session that runs the tests and evals and reports failures without fixing them, so the builder doesn't grade its own work.
4. **Logging.** Project hooks record every prompt, tool call, decision and reply. `/ai-report` turns those records into this page.

## Pushing the boundaries

- **An agent writing for an agent.** BUILD_PLAN.md is written for another AI to execute, with acceptance criteria and explicit stop-and-ask points. We test whether a planning agent can produce a spec that is good enough to build a full-stack app from an empty repo.
- **Live research into primary sources.** The planning agent pulled TY2026 and TY2027 numbers from IRS Rev. Procs published five days earlier, after the model's training cutoff. It also planned free regression tests from the exact tax amounts the Rev. Procs print at each bracket boundary.
- **Documentation tooling as part of the project.** Hooks and a custom Claude Code skill (`/ai-report`) produce this documentation automatically.
- _Planned:_ head-to-head comparisons of Claude Code and Copilot on at least 3 components (BUILD_PLAN §9), and an eval harness that shows whether the extra agents earn their place against a single agent.

## What we don't let AI decide

- **Tax numbers.** Every constant cites its IRS source line and is hand-checked by a human. Golden test values are copied from the IRS by a human, not generated.
- **Form-line mappings and glossary definitions.** These are data files that a human reviews, not model output.
- **Secrets.** API keys live only in the backend and are never committed. The logging hook also masks keys before writing anything.
- **Phase approval.** The execution agent stops for a human to approve each phase plan and each PR.

## How this was collected

- **Automatic:** [`.claude/hooks/ai-log.sh`](../.claude/hooks/ai-log.sh) runs on every prompt, tool call, reply and session start or end in Claude Code. It appends to `docs/ai-log/raw/<git-user>/<session>.jsonl`. These files are committed so everyone's report sees the whole team.
- **Backfilled:** the planning session ran before the hooks existed. It was imported from its Claude Code transcript with `ai-log.sh backfill`.
- **Redaction:** Anthropic and Voyage keys and `key=`/`token=` values are masked before anything is written.
- **Not captured automatically:** AI use outside Claude Code (ChatGPT, Copilot, Claude on the web). `/ai-report` asks about it, and those entries are marked as reported by a person.
