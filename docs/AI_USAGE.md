## Summary

We use AI as a **pipeline of agents with human checkpoints**, not as a single chat. A planning agent turned our design doc and slides into a build spec ([BUILD_PLAN.md](BUILD_PLAN.md)). An execution agent now builds the app from that spec one phase at a time. Phase 0 (scaffold) is done and passes every acceptance check. Neither the planning agent nor any human gave the execution agent extra instructions beyond the spec. Of our three sessions, we tagged two as **partial**, overriding the AI's suggested "success" both times. The tools produced working results, but each needed real human intervention: sudo installs, Xcode, a push the agent was blocked from making, and a command it gave us that didn't run as written. ## How we work with AI

1. **Planning agent** (done, [`be960576`](prompt-log.md#2026-11-10--planning--claude-code-claude-opus-5-5--cnash03--session-be960576)). It reads the specs, asks us the open decisions as multiple choice, and writes a spec another agent can follow. The spec includes acceptance criteria and a list of points where the agent must stop and ask a human.
2. **Execution agent** (Phase 0 done, [`866029d7`](prompt-log.md#2026-11-10--phase-0--claude-code-claude-opus-5-5--cnash03--session-866029d7)). Our only prompt was "your plan to execute is in build_plan.md - do it - stop with questions". The agent restated the phase plan, stopped for approval, built it, ran the checks and stopped again whenever it hit something only we could do.
3. **Evaluation agent** (Phase 7, not yet run). This is a separate session that runs the tests and evals and reports failures without fixing them, so the builder doesn't grade its own work.
4. **Logging.** Project hooks record every prompt, tool call, decision and reply, and `/ai-report` turns the records into this page.

**Divergences from the plan so far:**
- **We added a human test gate.** BUILD_PLAN only asks for automated checks. In Phase 0 we refused to tag the session until we had run the app ourselves. That surfaced two problems the automated checks couldn't: a broken copy-paste command and an Xcode version mismatch.
- **The environment wasn't ready.** The plan assumed .NET, MAUI and Xcode were installed. The agent had to stop several times for installs only a human could run with sudo.
- **The agent deviated from BUILD_PLAN §2 on purpose.** `TargetFramework` stays in each csproj rather than in `Directory.Build.props`, because the multi-targeting App would break otherwise.

## Pushing the boundaries

- **An agent executing another agent's spec.** Phase 0 is the first real handoff. A one-line prompt pointed the execution agent at BUILD_PLAN.md. It restated the phase, stopped for approval, and built a 10-project .NET solution with CI, a health-checked API and a desktop shell. Its stop-and-ask points (sudo, Xcode, Docker) fired where the plan said they should.
- **Verifying without the right tools.** Before Xcode was installed, the agent compiled the App's components in a throwaway Razor library and served them in a browser preview, so we could test the UI before the desktop build was possible.
- **Live research into primary sources.** The planning agent pulled TY2026 and TY2027 numbers from IRS Rev. Procs published five days earlier, after the model's training cutoff.
- **Documentation tooling as part of the project.** Hooks and a custom Claude Code skill (`/ai-report`) produce this page. Running it also caught a bug in our own logging.
- _Planned:_ head-to-head comparisons of Claude Code and Copilot on at least 3 components (BUILD_PLAN §9), and an eval harness with a no-retrieval baseline.

## What we don't let AI decide

- **Tax numbers.** Every constant cites its IRS source line and is hand-checked by a human. A human copies the golden test values from the IRS rather than having them generated.
- **Form-line mappings and glossary definitions.** These are data files that a human reviews, not model output.
- **Secrets and system changes.** API keys live only in the backend and are never committed, and the logging hook masks keys before writing. Installs that need sudo, and pushes to GitHub, are done by a human.
- **Phase approval and outcome tags.** The execution agent stops for a human to approve each phase plan. We tag outcomes only after testing the result ourselves.

## How this was collected

- **Automatic:** [`.claude/hooks/ai-log.sh`](../.claude/hooks/ai-log.sh) runs on every prompt, tool call, reply and session start or end in Claude Code. It appends to `docs/ai-log/raw/<git-user>/<session>.jsonl`. These files are committed so everyone's report sees the whole team.
- **Backfilled:** `be960576` and `83171a0b` began before the hooks existed and were imported from their Claude Code transcripts with `ai-log.sh backfill`.
- **Corrected:** 9 events from `866029d7` were filed under the wrong author while Xcode was being set up. They were merged back into `cnash03`.
- **Written mid-session:** the `866029d7` entry was written by `/ai-report` while that session was still running, so the phase's entry could go in with its PR.
- **Redaction:** Anthropic and Voyage keys and `key=`/`token=` values are masked before anything is written.
- **Not captured automatically:** AI use outside Claude Code (ChatGPT, Copilot, Claude on the web). `/ai-report` asks about it. So far none has been reported.
