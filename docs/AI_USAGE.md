## How we work with AI

1. **Planning agent** (done, [`be960576`](prompt-log.md#2026-11-10--planning--claude-code-claude-opus-5-5--cnash03--session-be960576)). It reads the specs, asks us the open decisions as multiple choice, and writes a spec another agent can follow. The spec includes acceptance criteria and a list of points where the agent must stop and ask a human.
2. **Execution agent**, one session per phase. Phase 0 is in [`866029d7`](prompt-log.md#2026-11-10--phase-0--claude-code-claude-opus-5-5--cnash03--session-866029d7), Phase 1 in [`cc8e27f2`](prompt-log.md#2026-11-10--phase-1--claude-code-claude-opus-5-5--cnash03--session-cc8e27f2) and Phase 2 in [`133e0d28`](prompt-log.md#2026-11-10--phase-2--claude-code-claude-opus-5-5--cnash03--session-133e0d28). Each session restates the phase, stops for our approval, builds, runs the checks, and opens a PR. It stops again whenever it hits something only we can do.
3. **Side sessions** for setup and docs ([`0640c1d8`](prompt-log.md#2026-11-10--phase-1-setup--claude-code-claude-opus-5-5--cnash03--session-0640c1d8) for secrets, [`e3c316a6`](prompt-log.md#2026-11-10--docs--claude-code-claude-opus-5-5--cnash03--session-e3c316a6) for the partner setup guide, [`14adbac0`](prompt-log.md#2026-11-10--phase-2-setup--claude-code-claude-opus-5-5--cnash03--session-14adbac0) for Claude API access).
4. **Evaluation agent.** A separate session reviews finished phases against the plan, so the builder doesn't grade its own work. The first run ([`b1c9df54`](prompt-log.md#2026-11-10--evaluation--claude-code-claude-opus-5-5--cnash03--session-b1c9df54)) reviewed Phases 0 and 1. The Phase 7 eval harness is still to come.
5. **Logging.** Project hooks record every prompt, tool call, decision and reply, and `/ai-report` turns the records into this page.

It worked, but one session's commit picked up another session's in-progress edits ([`90a7b15`](prompt-log.md#2026-11-10--phase-1-setup--claude-code-claude-opus-5-5--cnash03--session-0640c1d8)). The plan assumes one agent at a time.
- **The spec was corrected from primary sources.** The agent departed from BUILD_PLAN where the real IRS documents disagree with it (Rev. Proc. section numbers, PDF editions, chapter heading format). Each departure is listed in PR #3.
- **The evaluator also fixed what it found.** The plan describes an evaluation agent that only reports. In [`b1c9df54`](prompt-log.md#2026-11-10--evaluation--claude-code-claude-opus-5-5--cnash03--session-b1c9df54) we read its findings, picked the two to fix and had the same session fix them. - **Different models for dev and production.** BUILD_PLAN names one model. Local runs now use Claude Sonnet 5.5 to halve the cost of testing; the deployed API stays on Opus 5.5. Answer quality on Sonnet hasn't been compared yet; the Phase 7 eval should run on the production model.
- **The environment wasn't ready.** The agents had to stop for sudo installs, Xcode, Docker and Voyage billing.

## Pushing the boundaries

- **An agent executing another agent's spec, and correcting it.** Two phases have now been built from BUILD_PLAN.md with one-line prompts. In Phase 1 the execution agent checked the spec against primary sources: it downloaded and probed all 9 IRS PDFs before writing the parser, and found two places where the planning agent's spec was wrong (Rev. Proc. section numbers and stale PDF editions).
- **Measuring against real data instead of trusting tests.** The Phase 1 chunker passed its unit tests on the first try, but the agent measured the size distribution on the real IRS PDFs, saw that a quarter of the chunks were tiny, and fixed it over 4 rounds ([`cc8e27f2`](prompt-log.md#2026-11-10--phase-1--claude-code-claude-opus-5-5--cnash03--session-cc8e27f2)).
- **A second agent auditing the first, using data rather than code.** The evaluation session ([`b1c9df54`](prompt-log.md#2026-11-10--evaluation--claude-code-claude-opus-5-5--cnash03--session-b1c9df54)) didn't stop at reading code and re-running tests (all green). It pulled all 1,487 points out of Qdrant and measured them: how many chunks are mostly numbers, and how many section labels are merged. That surfaced two problems the green tests couldn't show. After the fix it measured again: 0 and 0.
- **Acceptance checks as runnable commands.** `--spot-check` turns the plan's manual retrieval checks into a single command with PASS/FAIL output. It confirmed that the TY2027 and TY2026 standard-deduction chunks rank #1 and that the demo question finds Pub 970 p. 5.
- **Parallel agents.** Three Claude sessions worked on one branch at the same time: setup, docs and the build. One session's warning about Voyage rate limits came true in another. The cost was a commit that mixed two sessions' work.
- **Live research into primary sources.** TY2026 and TY2027 numbers come from IRS Rev. Procs published after the model's training cutoff. The Voyage client was written against the live API reference.
- **Documentation tooling as part of the project.** Hooks and a custom skill produce this page, and running it has caught problems in our own process: misfiled log events, and a commit message that didn't match its diff.
- _Planned:_ head-to-head comparisons of Claude Code and Copilot on at least 3 components (BUILD_PLAN §9). **The PDF chunker and the Voyage client were two of the suggested candidates, and both are now built without a comparison.** That leaves the tax calculator and the citation chip UI. An eval harness with a no-retrieval baseline is also planned.

## What we don't let AI decide

- **Tax numbers.** Every constant cites its IRS source line and is hand-checked by a human. A human copies the golden test values from the IRS rather than having them generated.
- **Which document edition is the right one.** The ingestion pipeline stops if a PDF's cover year or sha256 doesn't match the manifest, and a human confirms the edition table (BUILD_PLAN §12 item 2).
- **Form-line mappings and glossary definitions.** These are data files that a human reviews, not model output.
- **Secrets and system changes.** API keys live only in user-secrets or backend settings, never in chat or commits. We log in to Claude ourselves (`ant auth login`); the agent only checks `ant auth status`. The logging hook masks keys, and the agent shows stored secrets only as `****`. Billing, sudo installs and pushes to GitHub are done by a human.
- **Phase approval and outcome tags.** The execution agent stops for approval of each phase plan. We tag outcomes only after testing the result ourselves.

## How this was collected

- **Automatic:** [`.claude/hooks/ai-log.sh`](../.claude/hooks/ai-log.sh) runs on every prompt, tool call, reply and session start or end in Claude Code. It appends to `docs/ai-log/raw/<git-user>/<session>.jsonl`. These files are committed so everyone's report sees the whole team.
- **Backfilled:** `be960576` and `83171a0b` began before the hooks existed and were imported from their Claude Code transcripts with `ai-log.sh backfill`.
- **Corrected:** 9 events from `866029d7` were filed under the wrong author while Xcode was being set up. They were merged back into `cnash03`.
- **Written mid-session:** the `866029d7`, `cc8e27f2`, `b1c9df54` and `14adbac0` entries were written by `/ai-report` while those sessions were still running, so each phase's entry could go in with its PR.
- **Redaction:** Anthropic and Voyage keys and `key=`/`token=` values are masked before anything is written.
- **Not captured automatically:** AI use outside Claude Code (ChatGPT, Copilot, Claude on the web). `/ai-report` asks about it. So far none has been reported.
